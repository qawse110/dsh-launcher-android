# 2026-09-05

## 修复：dsh web 启动崩溃 Could not load the "sharp" module (android-arm64)

现象：dsh 升级到 0.1.2-rc.1 后，`dsh web` 90 秒未就绪。cordis-plugin-loader 在
`Entry._init` 动态 import 插件入口时，插件顶层 `import sharp` 抛
`Could not load the "sharp" module using the android-arm64 runtime`（libvips 无
Android 预编译产物），AggregateError 上抛 → `Include._apply` 失败 → boot 中止。

已有的 `stub-dsh.mjs` sharp 补丁没生效，推测原因（未取得设备 install_log.txt 实证）：
1. `findPkg` 只返回第一个命中副本，.pnpm 多版本共存时漏打（已本地复现）；
2. pnpm 从 store 硬链接落盘，store 文件 0444 → writeFileSync EACCES，被外层
   try/catch 吞成一行 WARN；
3. pnpm 重新 materialize 覆盖补丁；stub 被 `apk:X|dsh:Y` marker 跳过。

改动（双防线）：
- `assets/stub-dsh.mjs`：新增 `writeFileForce`（先 chmod 644，失败则 unlink 重写）、
  `findPkgAll`/`findNestedPkgAll`（遍历全部副本）；失败逐条 WARN + 汇总计数；
  额外把 shim 落到 `$HOME/sharp-shim.cjs` 作为运行时兜底源。
- `assets/fs-loader.mjs`：resolve 期把裸说明符 `sharp` 重定向到 `$HOME/sharp-shim.cjs`
  （该改动的第二道防线，与安装顺序/副本数/写盘权限无关）；resolve 由 async 改同步，
  以便 registerHooks 与 register 共用。
- `assets/fs-register.mjs`：优先 `module.registerHooks()`（覆盖 CJS require，
  Node ≥22.15），仍保留 `module.register()`（覆盖 worker/子线程）。
- `DshFlow.kt#runAndroidStubOnce`：marker 命中但 `$HOME/sharp-shim.cjs` 缺失时也重跑 stub。

验证（临时环境，已清理）：造两个 sharp 副本 + 一张 4x3 PNG ——
- 改前只打 1 个副本，改后 2 个副本 8 个入口全部打上；
- 把副本恢复成抛错版本后，无兜底崩溃、有 `--import fs-register.mjs` 时
  ESM import 与 CJS require 均走通，PNG metadata/raw 解码正确；
- `node:fs/promises` 重定向回归通过（link 仍被兼容层顶替）。

## 真机更新后 sharp 仍崩的真正根因（commits a77ae89 前后 → 80163b8）
- **marker 跳过 stub**：runAndroidStubOnce 的 marker = `apk:<versionCode>|dsh:<版本>`，
  历史构建 versionCode 恒为 37 → 装带新补丁的 APK 更新后 marker 仍命中 → stub 被跳过，
  补丁从未真正执行过。修复：marker 绑定 stub-dsh.mjs 内容指纹（AssetSync 新公开
  `fingerprint()` = 长度+头 64KB CRC32），脚本一变必重跑，旧格式 marker 自动失效重跑。
- 加固（a77ae89 后的 33966272340 构建）：fs-loader 在 sharp-shim.cjs 缺失时自补
  最小 Proxy 桩（防线 2 完全自持）；拦截扩到 @img/sharp-*；新增 $HOME/fs-loader.log
  诊断日志；fs-register 两套钩子注册各自 try/catch；startDshWeb 启动前输出
  `compat: fs-register=... sharp-shim=... cli=...` 状态行。
- 教训：排查「补丁没生效」先查触发条件（marker/缓存），再查补丁本体。
- 产物：dsh-launcher-debug-r245-80163b8.apk（run 33966272340）。

## 第五、六环：token 401 + provider-headers 模块表缺失（commit 1fa5c7a，r248）
- 问题1「自动跳转不含 token」：dsh web 带 token 认证（每次启动轮换），
  WebViewActivity load 裸地址只拿到 401/403。修复：DshFlow.webToken()/webUrl()
  从 web.log 尾部 64KB 提取 `token=<...>`（正则 findAll 取最后一条），拼进 WebUI 地址。
- 问题2「Failed to load plugins: dsh-provider-headers client-modules missed
  the module table」：该插件浏览器半区 client.js require("@deepseek-ai/dsh-client-runtime/client")，
  旧 dsh 本体 0.1.2-rc.1 的 client-modules module table 未注册此外部
  （build-time externals drift；其他插件用的 dsh-client-ui-primitives 有注册所以没炸）。
  client.js 里该模块只用 createSnapshotStore，stub 内联等价实现
  （update=JSON 深拷贝草稿改写后通知订阅者）绕开 module table；幂等，缺模式 WARN 跳过。
- 关键知识：内置插件在 prebuilt.tgz 的 third_party/ 下（files/plugins/），
  不在 node_modules；client.js 是 window.__ModuleLoader__.load({factory(require)}) 格式。
  dsh-provider-headers 不在公共 npm（registry 404），只能从 prebuilt 取源码分析。
- 验证：vm 模拟宿主组装 patched client.js（require 不再触达 module table）+
  apply(ctx mock) 全链路 PASS；stub 二次运行幂等；compileDebugKotlin 过。
- 产物：dsh-launcher-debug-r248-1fa5c7a.apk（run 33970280259）。
