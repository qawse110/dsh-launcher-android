# 跑分总账 · 0.9.0-beta-1（2026-10-23）

> 这份文档回答一个问题：**这个插件在什么情况下值得开、什么情况下不如不开。**
> 所有数字可由 `po06/scripts/bench-dims.mjs` 重跑复现；缓存命中时不花模型调用。

## 方法

- 每用例 4–5 次调用：优化 1、工作 A/B 各 1、**评审 2 次（X/Y 顺序互换）**；
- 评审不知道哪份带注入；两次一致才算胜负，相反记「不可判定」（单评噪声与效应同量级，实测过）；
- 两侧同模型、同「2000 字以内、可贴关键代码」约束；
- 判据：exec 可执行性 / spec 具体度 / risk 风险与验证（1–5）。

## 成本（D3）

- 优化器每次 ≈ **2318 token**、**12 秒**（p50）；
- 注入包平均 ≈ **1137 字符 / 517 token** 进入工作模型上下文；
- **每轮固定增加 ≈ 2.8k token + 12 秒**；
- 对比：用户手工把愿望改写成规格，一次通常要 1–3 分钟。

## 怎么用这份证据

| 你的输入 | 建议 |
| --- | --- |
| “做个 X，要 Y”（只有要求） | 开。方向增益真实存在，但要接受它对“立刻能跑”的产物不占优 |
| 贴代码问 bug / 要决策 | **开**。两场全胜，且多命中预埋根因 |
| 已经在跑复杂项目、给失败报告 | **开**。3 条里 2 条胜，失败归因更到位 |
| 已经写好精确规格/步骤 | **关**（跳过优化）。两场全负，且规格本身没被破坏——它只是稀释执行 |

## 已知局限

- 样本小（D2/D4 各 2 条，D5 3 条），只能看方向；
- 评审与被评同族（deepseek-flash），存在同偏好；判据对审美型产物不敏感（D1 的两条不可判定正是站点与架构图）；
- D5 的 `d5-render` 出现“机械判据更优但评审判基线胜”的分歧，说明判据本身仍需校准。
