## 最重要的一条：D4 是真实反效果

两条精准提示词（一条给了完整参数规格，一条给了既定实现步骤）里，**注入版都输**，
而机械检查显示规格**一条都没被破坏**（5/5、4/4 全部保留）。也就是：

> 它不是“把用户的要求改坏了”，而是“在用户已经说清楚时，**多给了一层方案建议**，反而稀释了执行”。

这与插件自身的定位一致：它假设用户给的是“愿望”而非“规格”。当输入已经是规格时，它仍在补方向建议。

## 建议的动作（按性价比排序）

1. **精度闸门（推荐）**：检测到输入已含具体参数/步骤（数值密度、祈使+参数、编号步骤）时，只产 0–2 条建议或直接空包，把决定权交回工作模型；
2. 保持 D2/D5 现状（这两维是真实增益）；
3. D1 的“要能跑的东西”场景可考虑把建议偏到“验收与风险”，而不是“造型与结构”。

## 局限

- 期间有两次并发跑分写同一目录，最终数字取自最后一次**一致口径**的运行。
